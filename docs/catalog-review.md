# Catalog review for 0.1.0

The milestone specifies 23 products and 28 overlays without naming the entries. This is a proposed inventory assembled for this release. Reconcile it with the original if that list becomes available. Each row describes one candidate. “Reuse” identifies the nearest implemented owner for the stated scope. “Defer” identifies evidence needed to justify another implementation.

## Product candidates

| Candidate | Disposition and distinguishing evidence |
| --- | --- |
| Agent skill | Keep. Invocation, failure handling and session handoff need a replay. |
| Facility | Keep. Existing site conditions and feasible circulation need site evidence. |
| Operating process | Keep. Case entry, handoffs and exceptions need an operating walkthrough. |
| Contract | Keep. Delegation and unresolved terms need a drafting handoff. |
| Reference guide | Add. A conflict between source editions and the correction path for readers survive even when no operating process is in scope. |
| Handbook | Reuse reference guide for maintained advice. Include process only for separately scoped operations. |
| Knowledge base | Reuse reference guide for content governance. Defer the retrieval platform to a software pilot. |
| Runbook | Reuse process for execution and reference guide for independently maintained instructions. |
| Workflow automation | Reuse process for the work and Security when the automation performs external actions. |
| Agent workflow | Reuse agent skill plus process if both invocation and an operating handoff are deliverables. |
| Services agreement | Reuse contract. The Milestone 7 pilot already exercises it. |
| Renovation | Reuse facility. Existing-condition evidence already has an owner. |
| Service operation | Reuse process for delivery responsibilities and exceptions. |
| Policy | Defer until a pilot distinguishes binding authority, adoption and exceptions from contract and guide. |
| Curriculum | Defer until learner prerequisites and transfer of learning have a pilot. |
| Software application | Defer pending a distinct user journey and delivery handoff beyond general plus Evaluation. |
| API | Defer pending a consumer compatibility and lifecycle pilot. |
| Data product | Defer pending source lineage and refresh commitments. |
| ML model | Defer pending representative training data and drift evidence beyond Evaluation. |
| Manufactured device | Defer pending tolerances, serviceability and physical verification. |
| Event | Defer pending a time-bound operational handoff distinct from process. |
| Research study | Defer pending a method, sampling and inference pilot. |
| Campaign | Defer pending a channel, audience and attribution pilot. |

Use the general base when a deliverable lacks a specialization. The largest uncovered families here are software interfaces, data products and manufactured devices. Their examples should establish a decision and evidence owner before adding required questions.
