# Self-discovery pilot

The product is the repository's interview skill. This desk pilot replays the
project brief as stakeholder evidence. It uses a recorded sensitivity assumption
to exercise both overlays. A second command process resumes from the saved
revision and adds the remaining evidence and open questions.

The [saved state](state.json) and [generated baseline](baseline.md) contain the
handoff, decision register, open questions, and preliminary readiness. The
replay leaves handling, authority, and evaluation ownership unresolved.

| Interview issue observed during the replay | Adjustment |
| --- | --- |
| Asking for scope after the brief already named Discovery would repeat an answer. | Use the supplied scope as evidence and ask only about a boundary that could change the first slice. |
| Overlap with future skills is relevant to the architecture but has little effect on the first interview. | Treat it as an optional dimension and defer follow-up. |
| Asking about data authority without first considering the sensitivity of stakeholder notes gets ahead of the facts. | Confirm applicability before using the overlay questions. This replay records the sensitivity assumption explicitly. |
| Retention and export authority are missing from the brief. | Preserve those as blocking questions instead of marking the Security dimensions covered. |
| The brief suggests an acceptance process but leaves the live sign-off criteria open. | Separate evaluation cases from acceptance ownership. |
| Questions about serialization, indexes, and deployment are premature at the stakeholder level. | Ask what the next session must recover and verify. |

For a live replay, ask the stakeholder to confirm the pilot classification and
resolve the open questions. Resume from the named state file in a fresh agent
session to check skill discovery and question selection. Use the
[live acceptance checks](../../docs/acceptance.md#stakeholder-question-delivery)
to verify dialog delivery and chat fallback.
